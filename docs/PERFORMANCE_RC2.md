# Phase 6 performance candidate — publication held

**Measurements complete; release acceptance is not complete.** Recovered on **23 October 2026 (Asia/Singapore)**. This is **v6.1.0-rc.2 on the existing Phase 6 application/updater**, continuing the later **Proactive Dialogue, Mouse Awareness & Personality Persistence** workstream. That attachment has its own ten-phase plan: Phase 7 interface is implemented; the interrupted work was Phases 8–9 performance/testing and Phase 10 delivery. [The checkpoint](DEVELOPMENT_CHECKPOINT.md) distinguishes these numbering schemes. No installed Mac application is changed. rc.1 and the new native test candidate remain drafts. Publication requires a fresh decision after reviewing this report, and is not recommended on the present evidence.

The accepted code preserves animation and facial fidelity and improves several Linux measurements, but **does not demonstrate an improvement in every scenario, elimination of the historical idle regression, stable iMac 30 FPS, or lower CPU/memory across the board**. Regressing shader/background/cursor experiments were reverted. Conflicting retained results are reported below rather than characterized as successful optimization.

## Results and release decision

The completed data comprise **615 Linux rendering cases** (531 original matrix, 27 cursor/input, 18 complete exported-player, nine extended exported-player, 12 project-player comparison, 18 historical-workload), **72 native Intel Mac project-player cases**, and **18 separate headless probe records**. All are retained with frame traces where collected. See [all tables and lossless evidence](benchmarks/rc2/REVIEW.md), [177 Linux scenario/build rows](benchmarks/rc2/session-summary-final3.md), [24 Mac rows](benchmarks/rc2/native-summary.md), and [explicit-source script profiles](benchmarks/rc2/headless-summary.md). Mean, median, P95, P99, FPS, CPU and sampled RSS are included, not just selected wins.

Below, values are medians of three run statistics, in milliseconds. These are **actual unmodified Linux exported players**, Low, 960×600, real local bridge with simulated browser/audio, 30 FPS target. Their method differs from the uncapped subsystem matrix.

| Scenario / statistic | Working repair | Updater rc.1 | Accepted rc.2 |
| --- | ---: | ---: | ---: |
| Idle mean / P95 / P99 | 33.58 / 41.32 / 65.24 | 34.57 / 47.07 / 74.60 | 33.33 / 40.53 / 50.53 |
| Simulated speaking mean / P95 / P99 | 33.38 / 40.46 / 59.16 | 33.55 / 41.25 / 51.64 | 33.72 / 40.56 / 80.83 |
| Extended idle, 1,800 frames: mean / P95 / P99 | 37.81 / 59.66 / 101.20 | 35.31 / 47.77 / 95.80 | 34.82 / 45.65 / 83.41 |

Idle improves versus rc.1 in these tests. Speaking mean is slightly worse and P99 increases; rc.2 speaking P95 spans **39.22–232.30 ms** across repetitions. Extended idle is still approximately **28.72 FPS**, with P95 above the frame budget. The 30 FPS cap is a scheduling target, not proof of meeting a 33.3 ms budget.

In the **uncapped Linux subsystem matrix**, Low idle mean/P95 improves from rc.1 **41.40/55.96** to **32.48/47.54 ms**; speaking from **34.14/49.79** to **32.94/39.27 ms**. Against the older working repair, Low idle P95 is still worse (**39.80 → 47.54 ms**). Low CPU is not uniformly reduced: idle **195.63 → 203.31%**, speaking **200.31 → 200.65%** (one logical core = 100%). Peak RSS is slightly higher in those cases (**420.51 → 423.49 MiB**, **561.78 → 565.12 MiB**). These are software-renderer process costs, not GPU utilization.

Important regressions versus rc.1 remain in the full matrix: Balanced sleeping P95 **65.32 → 97.91 ms**, High speaking **473.73 → 659.07 ms**, Low rain **74.80 → 81.94 ms**, 1120×700 speaking **45.24 → 54.24 ms**, reduced-viewport speaking **57.31 → 74.27 ms**, and Low crossfade **45.00 → 53.07 ms**. Even the effects-off Low case regresses (**44.18 → 65.82 ms**), so background removal cannot be assumed to cure these tails. High software-renderer cases are severely over budget; they were not omitted or mixed into a favorable Low aggregate. The separate cursor workload also has costs: speaking mean **30.13 → 33.21 ms**, listening **25.36 → 26.66 ms**, with the new input feature enabled only where implemented. Saved user controls remain available; no feature is silently disabled to improve the scores.

The **matched historical-workload rerun** (hidden UI, sunset, no real HTTP) is unfavorable: idle P95 is **41.42 / 32.67 / 56.96 ms** for working/rc.1/rc.2; simulated-talking mean **25.40 / 29.20 / 32.08 ms**. This does not establish elimination of the requested historical **57.1 → 65.7 ms** regression or preservation of the earlier **50.6 → 44.6 ms** speaking gain. Those original numbers come from a different shared-host session, and neither the new desktop environment nor a changed benchmark workload may be counted as a code speedup.

## What the profiles explain, and what remains unresolved

The original rendering component profile below shows rendering dominates. Fresh, fingerprint-checked headless probes show rc.1 → rc.2 character-tick medians of **0.12521 → 0.08687 ms idle**, **0.17635 → 0.12887 ms talking**, **0.27193 → 0.20968 ms seated**, **0.33471 → 0.21538 ms sleeping**, and **0.16769 → 0.14371 ms walking**. These sub-millisecond script differences cannot explain multi-millisecond or second-scale render tails. App-plus-character probes including the requested autonomy defaults have overhead of their own; all results are retained separately. Headless figures do not establish an application FPS gain.

The updater's sharper Low/Balanced face uses the original full-detail face instead of the working repair's face LOD. In the Low idle matrix, submitted primitives rise from **23,948 to 29,236** between working repair and rc.1, with **24 draw calls** for both. rc.2 retains **29,236 / 24**, unchanged character shaders, original textures, full animation cadence and contact correction. This is a known fidelity cost versus the old working version. It does not explain differences between rc.1 and rc.2, which use the same rendering resources. No face quality was reduced to hide that cost.

Native Mac CI confirms the same distinction. [Run 39846700428](https://github.com/kingstar3452/Aisora/actions/runs/39846700428), macOS **15.7.9 x86_64**, uses **Apple Software Renderer**, not a physical Intel iMac GPU. With the original eight Low cases and identical source/harness fingerprints, rc.1 → rc.2 idle mean/P95 is **277.61/319.45 → 294.88/332.44 ms** and speaking **274.16/314.13 → 299.57/331.61 ms**. Across states it runs approximately **3–4 FPS** at about one CPU core. Some seated/rest tails improve; idle, speaking and personality results do not show an overall win. CPU units were independently calibrated against process CPU time before scoring. [Calibration](benchmarks/rc2/accounting-calibration.json) and all 72 runs remain available. These very slow software-renderer results cannot be advertised as Ventura/iMac performance or combined with Linux figures.

Shared-host variation, software-renderer saturation, process high-water memory and recorded Linux CPU throttling limit causal attribution. They do **not** prove that every regression is external noise. No physical GPU timings are available, and the remaining historical, High and Mac regressions are **not conclusively explained or fixed**. The tested candidate is preserved for review, but release readiness and the all-scenarios performance objective remain open.

The 1,800-frame matrix idle rc.2 RSS start-to-end changes are **−5.38, +0.016, +0.090 MiB**. This short observation does not show monotonic growth in that workload and does not prove the absence of leaks. Fresh-process exported runs retain their own memory samples; large sequential High/crossfade peaks are kept in the full tables. No general memory-reduction claim is made.

## Preserved quality and compatibility

The original VRM, every body/gesture animation, skeleton update cadence, expressions, full-detail face, textures, material quality, mouth amplitude envelope, bridge protocol, browser extension and user-data locations are preserved. The Low/Balanced face keeps rc.1's full LOD and facial lighting. High retains original MToon materials and 2× MSAA. Adaptive settings remain opt-in; the benchmark disables adaptation equally for all revisions to measure identical requested quality. Existing background-first adaptation and conversation resolution protection remain available in the app.

The opaque-background trial was reverted: longer actual Linux standalone idle repeats had median mean/P95/P99 48.54/92.51/155.10 ms versus rc.1 44.32/73.90/106.40 ms. Although isolated renderer A/B samples favored it, the application-level regression was unacceptable. Original background blending/crossfades are restored. A second trial using import-verified solid texture shaders was also reverted after three repeated Low screen comparisons worsened idle/speaking/listening means despite pixel equivalence. Original character shaders and VRM import settings are restored. Rest-pose IK reuses the pelvis/arm-parent FK snapshot and uses orthonormal inverses for its normalized quaternion bases. No animation step, contact correction or background effect is removed. The F3 overlay adds median/P99 data to its existing bounded 120-frame history and refresh-time sort.

The additional Voice cursor scheduling guard was also reverted after the 36-run input comparison showed worse mean/tail aggregates. It skipped unused hit-testing during conversations, but no reliable end-to-end benefit was demonstrated. The requested configurable autonomy defaults remain; proactive Voice is unavailable and only local text/events are implemented. These feature workloads are recorded separately from the original 59-case matrix.

## Profiling and rejected experiments

Before changing runtime code, the rc.1 component profile at Low, native 960×600, sunset, hidden UI, llvmpipe measured approximately 29.15 ms/frame total; viewport renderer CPU time was 23.76 ms and script time 0.43 ms. Background-only renderer time was 5.96 ms; character-only was 23.64 ms. Freezing the character solely for diagnostic isolation reduced renderer time to 17.45 ms. These component tests locate deferred skin/morph/draw costs; frozen-character results are **not scored application benchmarks** and the optimization never freezes animation. Software-renderer timer queries do not measure a physical GPU.

Two experiments were rejected and reverted: moving uniform color/UV arithmetic into vertex shaders increased tail latency in the screen tests; removing unused tangent streams did not demonstrate a repeatable end-to-end or RSS benefit and added mesh/preset complexity. Their raw screen runs are retained, including outliers. A later CPU-folded fragment-uniform experiment also passed 33 pixel checks but worsened the matched six-block Low animation comparison: median block mean/P95/P99 changed from 36.615/54.571/75.787 to 47.571/60.598/87.286 ms. That experiment remains isolated and was never applied to the accepted source. The accepted-candidate character shaders and meshes remain unchanged from rc.1.

Exploratory headless stage profiles use 330 warmup ticks and 1,800 timed ticks per state. They instrument script stages without a renderer and do not establish complete-app frame-time gains. An audit found that the older profile launcher’s path substitutions did not select the later snapshot/output names as intended; those records are retained as exploratory data, and superseded microsecond figures are withdrawn. The canonical repeated scene, full-app and native Mac comparisons use explicit source paths/fingerprints and remain separate.

## Repeated comparison method

Sources: previous working repair **bf2aee817f26da62a03187f9363580f57f71aeec**, updater **5ca43c50751a278ba5bfce462df147fc67cfffc8**, and accepted runtime **2142475b0cc9f8386e64929db1486746e9115e8b** (requested autonomy preferences plus conservative suppression for unknown paired Voice status and corrected cursor-driven head direction; the cursor scheduling experiment was reverted). Each is imported in its own source archive. Every process uses the same external harness and case catalogue; source/runtime/harness fingerprints are recorded. No concurrent local renderers or builds run during measurement. Native Mac CI runs on a separate machine.

Environment: official Godot 4.6.3 Compatibility, Linux x86_64, Xvfb 1920×1080, Mesa 25.0.7 llvmpipe LLVM 19.1.7, Dummy audio, LP_NUM_THREADS=2. The environment reports five Xeon Platinum 8573C logical CPUs with a four-core cgroup quota. This is a shared software-rendering environment, not an Intel Mac GPU test. Physical GPU utilization, hardware VRAM pressure, power draw and authenticated Voice latency are unavailable.

The 59 scenarios cover eight animation states across Low/Balanced/High, every personality gesture, day/night/rain/mist/branches/petals, effects off, crossfades, browser connected/disconnected and unavailable pairing, 960×600/1120×700/1920×1080 windows, native/reduced character viewports, explicit 30/15 FPS pacing and inactive Voice. Balanced is the existing middle preset referred to as Medium in the request. This is a coverage matrix rather than every possible Cartesian combination.

The retained scene harness explicitly advances the original character, bridge, state and environment subsystems with the main app process disabled. This keeps the original 59-case workload unchanged; the new autonomy/input pipeline is measured separately, and the unmodified exported-player runs include the complete application. Harness FPS is not silently substituted for complete standalone FPS. Each scene uses a fresh temporary config, fixed scenery/seed and the normal visible UI with Settings collapsed. All body/rest animations and IK remain active. Rest cases enter the settled pose before 60 rendered warmup and 180 measured frames. Idle memory cases use 1,800 measured frames. Uncapped cases tick animation at 1/30 s; deliberately paced cases use real frame delta. The real Python bridge serves loopback HTTP while a 100 ms synthetic browser/audio fixture drives listening or speech amplitude. No Chrome session, credentials, microphone or authenticated ChatGPT Voice is exercised. Idle browser-disconnected cases still exercise the real bridge; unavailable-pairing cases exercise its offline behavior.

Three sequential repetitions alternate project order. Every run/frame trace is retained, including slow runs and container throttling counters. Mean, median, P95, P99 and FPS summaries use medians of the three per-run statistics; percentiles are not pooled. CPU and sampled RSS cover each measured case, excluding warmup/startup; one logical CPU equals 100%. Engine-reported texture/buffer accounting is supplied separately from process RSS. Each build/repetition uses one sequential process; RSS includes allocator high-water effects from preceding cases, so the separate fresh-process exported-player runs are also retained. A short RSS plateau does not prove absence of all leaks.

The canonical rerun uses an owned persistent Xvfb server with `-noreset` and one explicit persistent desktop D-Bus session for every revision. An earlier unconfigured display produced an rc.1 X11 connection failure before scoring; startup-failure and tracing logs are retained. This development-environment correction is not an application or iMac speedup. Earlier datasets without that desktop session stay separate. The runner records session/display policy and rejects incompatible resume data. All 54 completed unchanged-working-version samples from the canonical first repetition were retained before restarting the remaining subset after the cursor direction correction; process RSS for that resumed subset has a fresh allocator high-water mark. Every scored slow frame remains included.

The historical 57.1/65.7 ms idle P95 and 50.6/44.6 ms simulated-speaking mean figures used hidden UI, disabled real HTTP and sunset. The expanded visible-UI/daytime/HTTP matrix is a different workload and cannot be substituted directly for those historical values. A retained-workload comparison must be reported separately.

## Local acceptance gate

Native Intel macOS 15 CI has now passed exported-app **headless startup**, actual XNU atomic exchange/reversal, strict/deep Apple signature validation, packed rig/face/autonomy rendering, and corruption rejection. It has **not** passed normal Finder/Internet launch acceptance: Gatekeeper with assessments enabled **rejects the quarantined ad-hoc app (exit 3)**. No quarantine stripping or security bypass is added. Target Ventura/iMac FPS/thermals, physical GPU profiling, real browser audio capture, authenticated ChatGPT Voice and Finder/LaunchServices update-health/rollback remain unverified. Keep the existing working installation.

Record the Mac display’s Retina/scaling setting and drawable pixel resolution as well as window size; a Retina window can render more pixels than a similarly sized Linux window. At identical Low/native window size and settings, compare the working app and candidate for 10–15 minutes idle and in an actual Voice conversation. Record F3 mean/P95/P99 and Activity Monitor CPU/memory; repeat after thermal warmup. Inspect eyes, mouth and hair occlusion in day/night/rain, and all body transitions/personality gestures. Exercise unfocused/minimized recovery, explicit 15 FPS mode and the optional reduced viewport. Check that Voice preempts pacing/sleep and retains visible amplitude-driven mouth movement. Repeat with the Godot editor and standalone app; Linux project-player/packed-resource checks do not establish native editor/standalone parity.
